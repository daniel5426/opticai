# Prysm agent search and reports

Last Updated: 2026-10-25

## Implementation

The clinic Artifact exposes `search_catalog`, `search_records`, `search_prescriptions`, `search_documents`, `report_catalog`, `run_report`, `read_report`, and `saved_reports`. Existing operational tools and legacy report/document APIs remain available. Model arguments never select a clinic, staff identity, patient authority, SQL, table name, or executable expression.

`services/clinic_catalog.py` owns authorized projections, row grains, field types, source relationships and query expressions. `clinic_query.py` compiles bounded, typed predicates and recursive AND/OR groups. Relationship groups apply their conditions to the same related record; patient-root semijoins avoid multiplying patients. The existing global-search endpoints reuse this authorization catalog and retain their response shapes and interface.

Search covers patients, families, exams, measurement components, regular/contact orders, appointments, referrals, medical notes, tasks, file metadata, billing, payments and inventory. Results carry matching fields, pagination and product navigation links. Deleted, merged-away and inaccessible source records are excluded. Structured-search pages share a stable relevance/ID ordering. File metadata and permanent document contents have separate coverage.

Prescription search retains component identity and pairs eyes only within one source/component. Rule version 1 averages the numerical differences across all supplied, applicable fields: SPH/CYL/ADD at 0.25 D, axis at circular 10-degree distance, PD at 1 mm, normalized exact VA comparison. Complete prescriptions may transpose cylinder notation; partial queries retain their supplied notation. An explicit zero cylinder makes axis inapplicable, including an absent recorded axis. Missing values otherwise cannot satisfy supplied fields. Results show original values and field differences; scores are retrieval distances, not medical confidence. The per-clinic readiness gate prevents partially backfilled coverage from being presented as complete. Legacy exact lookup remains usable during backfill and validates old component pairing against the source.

## Chat and attachments

The default SDK `AgentChatComposer` owns drafts, native file selection, previews, expansion, validation and submission recovery. Prysm uses the public `AgentChatComposerHandle.setText()` for selected editable blanks and preserves attachments. Empty clinic/patient chats each have exactly three deterministic, localized suggestion rows. Sidebar suggestions sit above the composer, which stays anchored at the bottom; main-page suggestions remain below the composer. The main assistant uses clinic scope; patient sidebar chats keep patient scope. Existing background, header and daily-brief entry point remain.

The main workflow accepts optional text, files and images. Native extraction handles text/Markdown/CSV/JSON/DOCX; the configured OCR model handles PDF/PNG/JPEG/WebP. Agents24 owns upload, extraction, retained content access and attachment history. Ordinary chat does not enqueue Prysm document jobs. Legacy jobs and protected links retain their existing seven-day policy. The workflow requests 18,000 seconds of native attachment retention.

The refreshed local SDK train is Chat React 0.5.37, React 0.2.24, Client 0.2.19 and CLI 0.3.31. Chat React's old/new builds share a version: confirm the exported handle after a canonical development-registry refresh. The repository lock currently uses that local registry; production installation requires the coordinated published build or another canonical local registry refresh.

## Reports

Version 2 definitions add nested relationship filters, distinct counts, registered derived fields, numeric derived metrics, explicit local date periods, comparisons and optional presentation settings. Derived metrics reference aggregate aliases and support ratio, percent and difference; zero denominators return null. Amount aggregates retain currency. Custom charts partition currency series. Shared invoices have one payer and are counted once. Collections use signed payments/refunds. Cumulative paid values are authoritative when present, with a payment-ledger fallback when absent; historical balances rewind dated future payments instead of adding the ledger twice. Analytics and reports share these definitions.

The requested-work worker materializes a run into a protected SQLite snapshot, then creates Excel and CSV from it. PostgreSQL source reads use repeatable-read isolation; a separate connection observes cancellation. Tables/page reads, charts, period comparison and both exports derive from the same execution. Report outputs attach once after the final assistant text, inside that response, including legacy export receipts restored from history. A two-column file grid shows only report names and one primary download button; it never renders readiness badges or a floating composer rail. Save and alternate-format exports remain under report details.

Optional `presentation` definitions choose `bar`, `line`, `area`, `pie` or `donut` charts using validated snapshot columns, display labels, and `show_table`/`show_stats`. This is declarative UI, with no generated HTML/JavaScript execution. Single aggregate rows per currency become stat cards; grouped distinct counts/averages are not summed into fabricated totals. Pie/donut charts require a single non-negative numeric series with a positive total. Invalid distributions stay explicit; accessible chart data, source tables and downloads remain available. Existing saved definitions/snapshots do not require conversion. API/Artifact/worker code must be updated together before accepting new presentation fields. Refinements create a new job. Current-page rows are bounded, previous-period preview is bounded, and exports contain the full execution including previous-period rows. XLSX text cells and CSV strings are formula-safe. Generated results expire after seven days.

Saved definitions are private to their creator, clinic and optional patient. Rename/delete use revision checks. Rerunning creates a new execution; saved relative business-health periods roll forward. Definitions persist until explicitly deleted. Old report definitions/jobs retain their reader and download contract.

Business health defaults to the last 90 completed `Asia/Jerusalem` days versus the preceding 90, with weekly trends. It distinguishes sales, collections, outstanding balances, billed-order count, average order value, new patients and recorded appointment activity. Calculation definitions, dates and missing-data limitations accompany results. Costs/expenses are insufficient for profitability claims. Timestamp filters cover whole Israel-local days, including offset/DST boundaries.

## Permanent document library: staged

`PRYSM_DOCUMENT_LIBRARY_ENABLED=false` is the default. Explicit maintenance queues authorized stored patient files; it does not ingest all historical files at startup. A unique file/revision mapping makes repeat queues idempotent and records ready/partial/failed coverage. The managed upload/pipeline owns extraction, chunking, embedding and indexing in a clinic namespace. Temporary chat attachments use their native lifecycle and never enter this library automatically.

Retrieval uses the separate native `document-search` workflow through the public embedded runtime. Prysm re-resolves the live staff session and checks each canonical evidence source against current file ownership, revision, deletion, clinic and patient scope after external I/O. Excerpts retain canonical locations/page references. Namespace selection alone does not grant record access. Retrieval candidate limits and incomplete coverage are explicit.

**Platform blocker:** including `document-search` in the package passes local/remote validation and plan but fails draft apply with a generic internal failure. An isolated copy omitting only that later resource applies and runs the core native attachment/search/report flow. The subsequent workflow is retained in `agents24-staged/`; the active package excludes it, so the completed core remains independently applicable. The staged README records the exact declaration to add after the fix. See [reproduction and IDs](../agents24-feedback.md). Permanent ingestion/retrieval and its live evidence shape remain unqualified until that resource applies and a known/unknown-document acceptance run passes.
