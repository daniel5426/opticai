# Prysm Agent production readiness plan

Last Updated: 2026-11-23

## Outcome

Clinic staff can find a record from a partial clue or an uploaded prescription, get a report they can verify and export, and review a proposed action before it changes a record. Each workflow shows its sources, coverage, progress and recovery options in Hebrew, English and French. Local development and production use the same published contracts, with separate data, identities and release verification.

## Local implementation status

The report worker now binds new jobs to the signed originating turn. An authenticated attachment lookup keeps the compact Save and Download row available even when model continuation fails. The agent selects and orders the inline report and search visuals. Legacy receipts still render. Hosted relays can read report pages from the API-owned snapshot volume through a scoped, signed request. Hosted availability checks the relay registration, and relay startup reports which child exited. These changes use existing job fields and require no database migration.

New uploads request transcript output only for audio. Rejected submissions retain the draft, and incomplete prescription coverage no longer shows a verified zero. Exact prescription matching narrows candidates before scoring, and structured search can expand a small set of Hebrew, English, and French terms. Production relay recovery, live OCR qualification, clinic index backfills, semantic retrieval, the permanent library pilot, and signed-in workflow canaries remain open.

## P0 — Restore production tools and make report delivery recoverable

1. **Restore the Railway relay.** Recover the exact child exit reason from the deployment’s protected evidence or reproduce the same image and published contract in the release qualification environment. Emit the child role, exit code and a sanitized reason category to production logs. Align the locked CLI, Python SDK, published Artifact and primary Agent without changing the stable production relay client ID. Verify the exact client is connected, each advertised Toolset is ready, the relay can execute an authenticated read against the production database, and the API-owned requested and summary workers are running. Keep the existing production service and release identities.
2. **Correlate the report and invocation at both ends.** Follow the real `run → invocation → Prysm job → receipt → resume → reload` chain. Persist safe correlation IDs, HTTP status, failure code and completion age on both sides. Test missing invocations, registration or credential changes, early receipt before suspension, worker death, reconciliation after a lost acknowledgement, stale callbacks and replay. Keep one report job per idempotency key. Route permanent rejection to a visible recoverable state and support reference.
3. **Show the completed report independently of model continuation.** Bind the authenticated report job to its initiating chat turn at acceptance. Surface computing, ready, failed, cancelled, expired and delivery-interrupted states with report-specific actions. A durable ready report must be available on the turn after reconnect or refresh even when model continuation fails. Resume or retry delivery against the same job. Keep the immutable snapshot and export in one authorized storage path. On separate hosted API and relay services, verify that `read_report` and paging can read jobs written by the requested worker, including after a restart.
4. **Make readiness feature-aware.** Include relay registration, a real scoped read, queue freshness, callback delivery and output persistence in internal readiness. Preserve ordinary clinic use during agent incidents. Give staff concise localized status and recovery actions. Alert on disconnected relay, blocked completion, rising queue age or an attachment rejection spike.

**Release gate.** Run the exact published build through a synthetic production canary and the local release-equivalent profile. Verify a real clinic-tool read, report totals against known fixtures, CSV/XLSX download, reconnect to the same job, and an injected callback failure that still shows the ready result. Confirm stage-specific observability can pinpoint the failure without logging patient records or provider payloads.

## P1 — Make photos, PDFs and search dependable

1. **Qualify attachment transport before tuning OCR.** Trace upload ID, admission, processing node and terminal stream. Verify browser and Electron uploads, persisted messages after refresh, MIME/size errors, retries and cancellation. Cover single and mixed uploads, JPEG/PNG, digital and scanned PDFs, multiple pages, rotation, blur, interrupted upload and expired sessions. Preserve the draft and attachment when submission fails. Show upload, extraction, search and result stages.
2. **Make prescription extraction typed and evidence-backed.** Return per-eye signed SPH/CYL, axis and optional ADD/PD/VA with page and source region. Normalize OD/OS and supported notation, including plus-cylinder equivalence and 0/180 axis. Preserve missing values and ask about unreadable signs or laterality. Keep values from each attachment and each prescription card together. Let staff correct extracted fields before running an ambiguous or low-quality search.
3. **Make prescription coverage measurable.** Backfill the versioned index incrementally per authorized clinic. Validate exam, glasses order, contact lens order and referral coverage with source counts, reconciliation and resumable checkpoints. Gate any claim of no matches on current coverage. Move candidate narrowing to indexed database queries before exact scoring where profiling warrants it. Keep deterministic numeric ranking with source links and explicit field-level differences. Present multiple candidates without selecting a patient automatically.
4. **Improve search from indirect wording.** Resolve Hebrew, English and French terms, aliases, abbreviations, transliteration and common misspellings against the typed clinic catalog. Combine indexed lexical results and semantic retrieval over appropriate text fields, then use structured filters and registered relationships for exact values, dates, balances and state. Rank patients and supporting records together. Show the interpreted filters and the evidence behind a result. Require provenance and fresh authorization on every returned item. Use targeted clarification when a result set is ambiguous.
5. **Pilot permanent document retrieval separately.** Qualify the staged ingestion and retrieval workflow with known and unknown documents. Keep indexing explicit and clinic-scoped. Verify access changes, revision replacement, deletion, retention, coverage and retrieval citations down to document page. Confirm that temporary chat attachments stay separate from the patient file library.

**Release gate.** In all supported locales, a synthetic image and two kinds of PDF must reach the correct authorized candidate and original exam without a manual workaround. Blurry or ambiguous values must ask for correction. A missing index must surface incomplete coverage. Evaluate exact, misspelled, indirect and multi-record queries against independently labeled results.

## P2 — Improve clinical workflows, reports and presentation

| Workflow to qualify | Expected staff outcome |
| --- | --- |
| Business health and custom reports | An accurate period comparison with clearly defined dates, denominators, currencies and coverage. Make sales, collections and outstanding balances distinct. Show unavailable cost and expense inputs explicitly. Export all rows in the same snapshot. |
| Patient preparation and order check | Link the right patient, dated exams, exact selected prescription, current orders and open follow-ups. Compare records without changing the clinical prescription. |
| Reception and scheduling | Combine a delayed order, recorded payment balance and suitable appointment slots. Recheck availability at approval time and return individual outcomes for a batch. |
| Clinical documentation and follow-up | Prepare a note, referral or task from supplied findings with a clear before/after review. Keep patient statements and practitioner findings distinct. Show a receipt after approval and verify zero writes on rejection. |
| Supply, briefs and campaigns | Validate delivery rows and units before a single reviewed inventory change. Keep brief facts and timestamps verifiable. Verify approved campaign drafts stay inactive and use channel consent. |

Use compact, consistent result components. Start report answers with the period and key finding, show up to three primary metrics, and show one chart when it answers a question. Keep detailed tables, metric definitions and downloads behind clear actions. In the synthetic desktop preview, the three cards fit and Hebrew previous-period totals ran into their change percentages. In the 390 px French preview, the third card wrapped and the chart plus table pushed detail down the page. Keep change percentages and previous values in separate bidirectional-safe elements. Give search errors search-specific language, and make incomplete coverage visually distinct from a verified zero. Localize statuses and use meaningful stage labels during long waits. Use the same accessible data table for the chart and visible detail where possible. Check full-page chat and the side panel at desktop and 390 px in Hebrew, English and French, with keyboard navigation and a screen reader.

## Qualification and rollout

- **Fixtures.** Seed two clinics and staff roles, duplicate names, old and new exam layouts, deliberately similar prescriptions, an unindexed clinic, synthetic attachments, empty periods, partial payments, refunds, two currencies and an order linked to a visit. Define expected IDs, facts and outcomes before running the model.
- **Continuous checks.** Add deterministic query/index and job-recovery tests, browser flow checks for the published contract, and scheduled synthetic model runs. Include hostile document instructions, role or clinic changes mid-run, attempts to skip approval, expired files, duplicate submissions and revoked source access. Record model, prompt, package, relay, SDK and app versions with routed environment. Measure warm and cold runs separately. Track grounded task completion, exact field extraction, ranking, duplicate writes, latency, cost and resume success.
- **Initial targets.** Zero cross-clinic leaks, missed approval gates, duplicate writes or wrong-patient identification in release acceptance. Require 100% signed field agreement on clean prescription fixtures. Target at least 95% top-three recall on the reviewed indirect-query set and at least 95% successful completion on the core synthetic workflow set. Target first useful state within 3 seconds at p95, indexed exact search within 5 seconds at p95 after extraction, and a typical report ready within 30 seconds at p95 on a defined clinic-size fixture. Use a visible durable job for longer work and publish sample sizes with measured results.
- **Release sequence.** Repair reliability first, then qualify the same exact release artifacts under the OpticAI CI contract. Recheck the exact production relay and workers before enabling staff access. Roll out to a pilot clinic with telemetry and expand after the representative scenarios pass. Keep flags for OCR search, permanent library and write workflows separately reversible. Roll back the affected capability or service on a failed canary while preserving jobs, artifacts and approvals.
- **Ownership.** Prysm owns clinic authority, query semantics, index coverage, report data and result UI. Agents24 owns invocation identity, durable waiting, continuation, attachment processing and provider behavior. Both sides own a shared contract test that uses the actual SDK and runtime.
